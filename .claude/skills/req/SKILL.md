# /req — 需求規格

## 參數

呼叫時傳入的 args 就是 `<domain> <需求描述>`：

- **domain** = args 的第一個詞（例：`passport`）。下文的 `<domain>` 一律代換成它。
- **需求描述** = args 的其餘全文。

args 沒有給 domain 時，先問使用者，不要猜。

## 步驟

1. 讀 `docs/<domain>/01-需求規格書.md`（若存在）的修訂紀錄。
   若有未上線的版次，而且這次要處理的不是那個版次，停下來問我要不要先處理它。
2. **在主線做需求訪談**，把會影響驗收的問題問完。範圍包括：
   - 目的、本版範圍與範圍外
   - 角色
   - 資料項目（欄位、必填、長度、格式）
   - 業務規則
   - 權限與語系
   - 驗收方式

   用選項式提問，一次最多 4 題。不要把釐清工作丟給 subagent。
3. 派 spec-writer，派工內容要寫明：
   - domain
   - 新建或修訂
   - 目標版次
   - 訪談摘要（逐條列出已決議事項）
4. spec-writer 回報後，把「待確認事項」原文呈現給我；我回答後，再請 spec-writer 更新文件。
5. 我核准後：
   - 01 的文件狀態與本版次修訂紀錄改為「已核准」
   - commit：`docs(<domain>): 01 需求規格書 vX.Y 核准 — <本版新增/修改的編號>`

停下來。下一步是 `/sa <domain>`。
